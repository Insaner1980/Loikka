# Native interactive acceptance

`-RegressionOnly` runs the focused F01–F04/F06–F11 correction checks against a fresh synthetic reference fixture: athlete startup/progress, signed change and season comparison, combined-event breakdown, filters, calendar number keys, viewer Tab/Shift+Tab/Escape and startup work-area bounds. It is exclusive with the other focused modes. F05 chart-label geometry and all six real Windows display/text combinations are covered by the dated scaling scripts and receipts under `.native-artifacts/fixes-20261015/`; the main harness does not change Windows scaling. Use the same mandatory `-Executable`, `-DataRoot` and `-EvidenceRoot` arguments with a new root on every run.

The window harness expects 1200×800 effective initial client pixels and 800×600 minimum client pixels, each limited by the actual monitor work area including the nonclient frame. It checks exact current-DPI sizes and that the initial outer window fits the work area. The R2 window-size measurements below describe the earlier behavior.

`Invoke-NativeAcceptance.ps1` drives the actual unpackaged WinUI executable through Windows UI Automation. It does not use browser mocks, coordinate clicks or a test web server. Run it in an interactive Windows desktop session after the native app has been built and with a **new** isolated data directory:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File native/Loikka.UiTests/Invoke-NativeAcceptance.ps1 -Executable C:\absolute\publish\Loikka.App.exe -DataRoot C:\absolute\new-synthetic-run -EvidenceRoot C:\absolute\test-evidence
```

The exact executable and data-root arguments are mandatory operational evidence; do not substitute an installed production app/data directory. An existing data root is rejected before launch. The script keeps the synthetic data/evidence for inspection, records apphost plus application/Core/Infrastructure DLL and PRI/configuration hashes before launch, OS/PowerShell identity and every owned process ID, and closes only the application processes it starts. The apphost EXE hash alone is insufficient to identify a .NET build because managed code can change without changing that host. The script never resets a user data directory or changes Windows display/text-scale settings. Its UTF8 BOM is intentional for Finnish literals under Windows PowerShell5.1.
